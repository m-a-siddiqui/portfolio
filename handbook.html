Context

The brief

A monitoring floor is not a queue of tickets. It is a fixed amount of footage, a fixed number of hours, and a set of people who have to be matched to both — continuously, fairly, and provably.

The problem

Coverage that nobody could prove

Around 410 client fleets need eyes on them through the day, each within its own contracted hours. Work was split by hand, tracked in spreadsheets, and reviewed after the fact. Nobody could answer the three questions that actually matter: who is covering what right now, what has gone unwatched today, and how do we know.

Attendance had the same shape. Hours were self-reported, breaks were remembered rather than recorded, and a night shift crossing midnight broke every total it touched.

The response

One system of record, two consoles

Allocation, attendance, footage requests and performance were collapsed into a single platform with one computation behind every screen. Operators get a board that tells them exactly what to review this hour. Supervisors get a live floor, a reconstructable day, and figures they can defend.

It runs on the spreadsheets the business already trusted — no migration, no new database, no change to how the company stores its own data.

Under load

Engineering decisions

Six problems that shaped the platform. Each one is a case where the obvious implementation was wrong, and the record shows why.

Decision 01 · Time

The day does not start at midnight

The failure

A shift running 22:00 to 07:00 was split across two calendar dates. Its output landed under two days, its break totals under two days, and its score under neither. Every night-shift figure on the platform was wrong, and only on nights.

The decision

Every stored date became an operating day running 07:00 to 07:00, applied uniformly — allocation, attendance, scoring, ordering. Hour 6 is the last hour of a day, not the first. Time parsing was replaced everywhere with operating-day-aware equivalents.

Outcome: a night shift is one continuous unit for measurement, pay and audit. Sixteen dedicated checks hold the boundary, including the hour either side of it.
Decision 02 · Data layer

A spreadsheet as a production datastore, inside its quota

The constraint

The business's records live in Google Sheets, and the read allowance is 60 requests per minute for the whole platform — not per user. Thirty dashboards polling continuously would exhaust it several times over, and a throttled floor is a stopped floor.

The design

Per-dataset caches with lifetimes matched to how fast each dataset actually changes; reads micro-batched into combined requests; related datasets prefetched together so a screen assembles from one round trip. Writes are throttled to meaningful movement only.

Outcome: a simulated full floor draws 33–38 reads per minute — comfortably inside the budget, with headroom for growth. Measured, not estimated.
Decision 03 · Compute

The metered resource was compute, not requests

The failure

The platform was suspended mid-shift. Not for traffic — requests were well within allowance — but for active compute: twelve hours against four. Profiling showed the day plan being recomputed three times per poll from identical inputs.

The decision

The planner was memoised on an input signature, sharing one computation across every panel of a request. Cost was then measured directly against a simulated floor rather than assumed.

Outcome: 51 ms → 13.6 ms of compute per poll, and a projected monthly cost cut from roughly 22 hours to 6. The optimisation was chosen from a measurement, not a hunch.
Decision 04 · Correctness

Clients appeared to move on their own

The failure

Operators reported clients shuffling between them with no shift change to explain it. The cause was a reference read returning partially under load: allocation is weighted by fleet size, so an incomplete set silently reweighted the entire floor.

The decision

Reads fail closed rather than returning half an answer. Concurrent requests for the same dataset collapse into one in-flight read. A result materially smaller than the last known-good one is rejected and the previous set retained.

Outcome: allocation proved deterministic across fifty consecutive runs on identical inputs, and the partial-read case is pinned as a permanent regression check.
Decision 05 · Integrity

A browser extension built to defeat the attendance rule

The threat

An extension was found on the floor whose only purpose was to stop the automatic break: it forced the idle reading to zero on every poll, synthesised mouse and keyboard events, patched the page's own timers, and clicked Resume if a break got through.

The decision

An extension runs with the page's privileges — it cannot be blocked from inside the page, and pretending otherwise would be theatre. So the signal was changed instead: for listed identities, inactivity is measured from recorded work, which no browser can fabricate. Separately, reported presence is cross-checked against output and disagreement is surfaced.

Outcome: the rule became unspoofable from the client, without accusing anyone. Enforcement ships observe-only and is enabled deliberately, per identity.
Decision 06 · Architecture

Two screens quietly disagreeing about one person

The failure

The same rule had been implemented twice — once for the operator's screen, once for the supervisor's. The copies drifted, and the two consoles began giving different answers about the same employee on the same day. It is the worst class of bug this system can have: both screens look correct.

The decision

Allocation, day-level coverage and scoring were each collapsed to a single implementation that both consoles call. Where a rule is shared, duplicating it is treated as a defect in its own right, and tests assert that no second copy exists.

Outcome: the two consoles are the same computation by construction. Every defect since has been captured as a check before being fixed — 522 of them now stand.
The short version

What the platform does

Ten capabilities that define the system. Everything documented after this exists to serve one of them.

01Operator · Supervisor · Automatic

Work is allocated by fleet size, not by headcount

Operators do not choose what to review. Every hour, each receives a defined set of clients, ordered by fleet size so heavy accounts are spread instead of stacked on one person. The allocation is computed once and read everywhere — the operator's board and the supervisor's grid are the same calculation.

In practiceTwo operators with the same number of clients are carrying the same number of vehicles, so their output can be compared fairly.
02Operator · Supervisor

Nothing sits unreviewed for a day without being named

An hourly view cannot answer "who has been waiting since this morning" — a client untouched all day looks identical to one seen an hour ago. The platform tracks coverage at day level: clients nobody has reviewed since the day opened, counted once no matter how many operators held them.

In practiceA supervisor can name every client that has gone unseen today, and which operator's hours the gap came from.
03Operator · Automatic

Attendance records itself, and records the truth

Clock-in, clock-out, breaks, early starts, overtime and week-offs are captured as they happen. Ten minutes without activity opens a break automatically — backdated to the moment work actually stopped, not the moment it was noticed.

In practiceA machine left running cannot hold a shift artificially active, and nobody has to remember to log anything.
04Operator · Supervisor

Performance is one number, and the working is shown

A 100-point score built from footage share, vehicles reviewed and break discipline. The operator sees the score and every figure behind it. The supervisor sees the whole floor as cards. Both read the same computation.

In practiceNobody is handed a rating they cannot check, and the two screens can never quote different numbers for the same person.
05Operator · Supervisor

Work never falls through a shift change

A footage request that cannot be finished before a shift ends is forwarded to a named colleague and arrives as a tracked follow-up. The receiving operator gets an amber indicator that follows them across every screen and animates periodically until the queue is clear.

In practiceNothing gets closed just to make a shift look finished, and the incoming operator cannot miss what they inherited.
06Supervisor · Automatic

An absence reallocates the floor in seconds, with an audit trail

A supervisor marks leave — a full day or a specific window — and that operator's clients are redistributed across the remaining floor immediately. Every movement is written to a log naming source, destination, client and hour.

In practiceAn unplanned absence does not leave clients unwatched, and the day can still be explained afterwards, line by line.
07Supervisor

Any day can be reopened and read in full

Every operator against every hour, with attendance, output, breaks and follow-ups — and the shift window shown in both forms where they differ: as rostered, and as actually worked after an early start or approved overtime.

In practiceA question about last Tuesday is answered from the record, not from memory.
08Platform · Automatic

One identity, one active session

Signing in anywhere terminates every other session for that identity. One name cannot be worked from two desks, an abandoned machine cannot keep reporting presence, and a break opened at one desk cannot be resumed from another.

In practiceAttendance always describes the desk somebody is actually sitting at.
09Supervisor · Automatic

Reported presence is cross-checked against recorded work

The browser says somebody is at their desk; the record shows what they produced. When the two disagree, the platform surfaces it. Where presence cannot be taken at face value, inactivity is measured from recorded work instead of the browser — a signal that cannot be simulated from inside a tab.

In practiceAttendance figures hold up even against deliberate attempts to manipulate them.
10Supervisor

The record starts before the platform did

Work recorded in the months before this system existed is carried forward in the same shape as live data. Monthly totals are kept as monthly totals — never sliced into days they cannot honestly be divided into.

In practiceYear-on-year reporting is possible from day one, without pretending the year began when the software did.
Foundations

Critical rules

These are the decisions everything else is built on. They are enforced in code, verified automatically on every change, and they are the reason two screens can never give two answers to the same question.

The six that matter most
Get these wrong and the numbers stop meaning anything

Each of these protects a figure somebody is measured, paid or audited on. They are absolute — there is no configuration that turns them off.

  1. The operating day runs 07:00 to 07:00

    Every date the platform records is an operating day, not a calendar date. Work logged at 02:00 belongs to the shift that began the evening before. Without this, every night shift is split across two days and neither total is true.

  2. One rule, one implementation

    Allocation, coverage and scoring each exist exactly once, and every screen calls the same code. A rule that is copied is a rule that drifts — and two screens quietly disagreeing about the same person is the worst failure this system can have.

  3. A break is backdated to when work stopped

    Not to when inactivity was detected. A closed laptop and a walked-away desk both produce an accurate record rather than a flattering one, because the gap is measured from the last real activity.

  4. Partial data is never treated as fact

    If reference data cannot be read in full, the platform keeps the last complete answer rather than adopting the incomplete one. A partial read would silently reweight the entire floor and move clients nobody asked to move.

  5. Attendance history is never deleted

    Corrections mark superseded records instead of removing them. What was recorded, and what was later corrected, both stay auditable — an attendance trail that can be quietly rewritten is not a record at all.

  6. Nobody is scored for a day they did not work

    Scoring applies only to operators the operating day actually belongs to. An absent operator gets no score rather than a misleading one — a flattering number for a day somebody was not there is worse than no number.

  • ▸
    Allocation is deterministicSame inputs, same split, every time. Clients never move without a real event, and every move is logged.
  • ▸
    Overlapping absences count onceBreak totals are the union of intervals, not the sum of rows. Nobody is charged twice for one minute.
  • ▸
    The most recent record winsWhere a client is reviewed twice, the later entry is authoritative — and the earlier one remains for the trail.
  • ▸
    A save writes the whole recordEvery field is submitted together, so a partial write can never blank what the operator did not touch.
  • ▸
    A long break does not reassign workTime away never moves somebody's clients. The board an operator returns to is the board they left.
  • ▸

Shift context

Operator workspace

Shift, break and overtime

Attendance is captured as a by-product of working, not as a separate task.

Start shift
A single action. Starting ahead of the rostered window is recorded as an early start, and the board opens against the effective window rather than the scheduled one.
Manual break
Opens a full-screen state that suspends work until resumed, so a break is unambiguous on both sides of the record.
KeyAutomatic break
Ten minutes without recorded activity opens a break automatically, backdated to the moment activity stopped. A machine left open cannot hold a shift artificially active.
Overtime
Extends the shift by three hours, once per operating day, and extends the board's hours to match.
End shift
Closes the shift. Past the rostered window the action is promoted so it cannot be overlooked.
Automatic close
A shift left open is closed by the platform after a thirty-minute grace period, so no record runs indefinitely.
Break ledger
Every break of the day with start, end and duration, plus the day's total — counted as the union of intervals so overlapping records are never double-charged.
KeyCross-midnight continuity
A shift and any break opened within it remain the same records after midnight. A break started at 23:52 is still resolvable at 00:05 — the case that breaks most attendance systems.

Under the hood

The engine room

Nobody operates these. They run continuously, and the accuracy of every screen depends on them.

Performance scoring

ComponentWeightBasis
Footage40Share of the day's total footage requests raised under this operator. The heaviest single weight, because every request represents a customer waiting.
Vehicles60Vehicles reviewed against a target of 800. Full credit at target, no additional credit beyond it, and no cliff for falling slightly short.
Break−20Applied when the day's total break time exceeds one hour, measured as the union of intervals.

The computation exists once. The operator's score and the supervisor's card are the same number by construction, not by coincidence.

Allocation

KeyWeighted distribution
Clients are ordered by fleet size and assigned heaviest-first, so total vehicle load is balanced rather than client count. Every client carries at least unit weight, so an account with no fleet data on file is still allocated rather than dropped.
Client review windows
Each client carries its own hours, and is only ever allocated within the window it is contracted for.
Roster awareness
Allocation respects shift windows, night shifts, week-offs, per-operator hour overrides, approved leave and overtime — all applied from the same computation.
KeyStability under load
Concurrent requests for the same reference data are collapsed into a single read, and a reference set that returns materially smaller than the last known-good one is rejected rather than adopted. This is what stops clients appearing to shuffle when nothing on the floor has changed.

Data layer

Read budgeting
The platform works within a fixed read allowance shared across the whole floor. Reads are cached with per-dataset lifetimes, batched into combined requests, and prefetched together, so a screen assembles from one round trip rather than a dozen.
Write economy
Activity timestamps are written only when they have moved meaningfully, and are stored on the existing shift record rather than a separate log — no extra dataset to maintain, and no write amplification from routine polling.
Computation caching
The day plan is computed once per set of inputs and reused within its lifetime, rather than recalculated for every panel that displays it.
Daily rollup
Each operating day condenses to one row per operator, which keeps long-range reporting fast without retaining every client-hour indefinitely — and is the same shape historical records were imported into.
Graceful degradation
If a dataset is briefly unavailable, screens render what they can and state what is missing. A partial failure does not take down a working floor.
Under the hood

Integrity and anti-tamper

Attendance that measures itself has to be resistant to being told what to measure. This is how that is handled.

KeyTwo clocks, cross-checked
The browser reports presence; the record shows output. When one insists an operator has been at their desk all afternoon and the other shows no work in that period, the platform flags the disagreement for a supervisor rather than trusting either side.
KeyWork-based inactivity
Where browser-reported presence cannot be relied on, inactivity is measured from recorded work instead. The automatic break is then driven by output — a signal that cannot be simulated from inside a browser tab.
Supervisor-controlled
That stricter measurement applies only to identities a supervisor has listed, and can be suspended per identity at any time. It is configuration, not a code change, and takes effect within minutes.
KeySession enforcement
One active session per identity. A second sign-in ends the first, closing the gap where an unattended machine could keep a shift looking alive, or a break opened at one desk could be resumed from another.
Resume is verified presence
Ending a break counts as confirmed presence in its own right, so an operator returning to work is never immediately placed back on break by the same rule that opened it.
Reopen protection
Guards prevent a break being reopened moments after it was closed, and prevent duplicate break records from concurrent requests.
Design position. None of this is enforcement for its own sake. Every mechanism here exists so an honest operator's record is accurate, and so a supervisor comparing two people is comparing like with like. Restrictive behaviour is introduced in observe-only mode first, and enabled deliberately.

Platform and assurance

How the system is built, secured and verified.

Access

Roles
Two: operator and supervisor. The role determines which console loads and what each interface may read and write, enforced server-side on every request rather than by hiding controls.
Signed sessions
Authentication issues a signed token held in an HTTP-only cookie. Every endpoint verifies identity and role independently.
Session registry
The current sign-in for each identity is recorded centrally, which is what makes single-session enforcement reliable across devices.

Assurance

KeyAutomated verification
522 automated checks across 24 suites — allocation, attendance, breaks, night-shift boundaries, scoring, coverage, caching and interface behaviour. Roughly 7,500 lines of tests against 18,000 lines of application code. Every change runs the full suite before it ships.
KeyIsolated test harness
Tests run against a simulated data layer, so the entire suite can be executed mid-shift without reading or writing a single row of live data.
Interface verification
Every screen, operator and supervisor, is rendered in a real browser against controlled data and checked for failure before release — the class of fault server-side testing cannot catch.
KeyRegression capture
Every defect found in production is turned into a permanent check before it is fixed, so it cannot return unnoticed. The suite is a record of everything that has ever gone wrong and has been made impossible since.
Capacity measurement
Compute cost per request and read volume are measured directly against a simulated full floor, so scaling decisions rest on figures rather than estimates.
Fault containment
Interface faults are contained to the panel they occur in. One failing component does not take the screen down.
